# Device Knowledge: JOY-IT / Juntek JDS6600

## 1. Device profile

The JDS6600 is a separate signal generator, not part of the oscilloscope. The
application supports the JOY-IT/Juntek JDS6600 and JDS6600-LITE through the
canonical profile id `jds6600`. The command package declares
`configured_device: jd6600`; the application setting is `jds6600`. Both
spellings are normalized to the same profile.

Known models and their frequency limits, from `docs/manual.md` section 10.2:

| Model | Sine | Square | Triangle / pulse / other |
|:------|-----:|-------:|-------------------------:|
| JDS6600-LITE | 15 MHz | 15 MHz | 6 MHz |
| JDS6600 | 60 MHz | 15 MHz | 6 MHz |

Identity: `*IDN?` returns `manufacturer,model,serial,N/A`, for example
`JOY-IT,JDS6600-LITE,12345,N/A` (system prompt signal-generator reference).
The configured profile and the detected identity are separate values; the
application reports both.

Firmware: not specified in the repository. Do not assume a firmware version or
a firmware-specific behaviour that is not documented here.

## 2. Operating model

- The AI Chat controls the generator through the semantic tools
  `read_signal_generator_status`, `set_signal_generator` and
  `signal_generator_action`. These tools require a signal-generator keyword in
  the user request (source: tool descriptions and frontend prompt).
- The command package `jds6600_scpi_commands.json` is the authoritative list of
  SCPI commands for this profile. The agent must use the registry; it must not
  invent commands, units or query forms.
- A change request is applied in this order: waveform, frequency, amplitude,
  offset, duty, phase, output. The order matters because the device limits
  depend on the waveform and the frequency (source: `set_signal_generator`
  tool description).
- `*RST` returns both channels to a safe state: outputs off, sine, 1 kHz,
  1 Vpp, 0 V offset, duty 50 %, phase 0 (source: command description and
  `docs/manual.md` section 15.1).

## 3. Channels and outputs

- Two channels, CH1 and CH2. The SCPI channel suffix is `1` or `2`; no other
  channel is accepted.
- `OUTP<n>:STAT ON|OFF|1|0` switches one output. The documented short forms
  `OUTP<n> <state>` and `OUTP<n>?` are equivalent (command package aliases and
  `docs/manual.md` section 15.3).
- `OUTP:ALL ON|OFF|1|0` switches both outputs. Its query returns `1` only when
  both outputs are on.
- Enabling an output produces a real electrical signal. Do not enable an
  output just because a change request seems to imply it; the user must ask for
  it, and the load/connection state must be considered.

## 4. Waveforms

Supported canonical names, from the command package and `docs/manual.md`
section 15.5:

`SIN, SQU, PULS, TRI, PSIN, CMOS, DC, HALF, FULL, POSL, NEGL, NOIS, ERIS, EDEC,
MTON, SINC, LOR`

Accepted aliases:

`SINE, SQUARE, PULSE, TRIANGLE, NOISE`

- FY6900-only names such as `RECT`, `TRAP` and `RAMP` are rejected by the
  JDS6600 with SCPI error `-222` (source: command package and
  `docs/manual.md` section 15.5).
- The application does not map FY6900 names to JDS6600 presets. An unsupported
  name is rejected; it is never silently changed.
- `ARB` is not available. `SOUR<n>:FUNC ARB` returns `-113`.

## 5. Parameter dependencies

- Frequency limits depend on the waveform and the detected model (see section
  1). The package does not define numeric ranges; the driver validates against
  the detected model.
- Minimum frequency: 0.01 Hz (source: `models.dart` and the system prompt
  signal-generator reference).
- Amplitude limits depend on the frequency: 20 Vpp below 10 MHz and 10 Vpp
  at/above 10 MHz (source: `docs/manual.md` section 10.2 and `models.dart`).
- DC-offset range: ±9.99 V (source: `docs/manual.md` section 10.2 and
  `models.dart`).
- Duty cycle: 0–100 % on the JDS6600; the duty command applies to the
  square/pulse shape (source: `docs/manual.md` section 15.6).
- Phase: 0–360°. The JDS6600 has one global CH2-vs-CH1 phase register, so
  `SOUR1:PHAS` and `SOUR2:PHAS` address the same value and both queries return
  it (source: `docs/manual.md` section 15.6 and
  `SignalGeneratorService.setPhase`).
- The package does not specify resolution limits. Do not invent them.

## 6. Typical operating workflows

1. Read the current status first when the request depends on the existing
   waveform, frequency, model or connection state.
2. Set the waveform before frequency, amplitude and offset, because the limits
   depend on the waveform and the frequency.
3. Set frequency before amplitude and offset.
4. Apply duty and phase after the waveform and frequency. Remember that phase is
   global on this device, even when the request names CH1 or CH2.
5. Switch the output on only when the user explicitly asks for it.
6. Query the affected value back when the operation kind is `setter_query`, and
   report the actual device value.

Safe reset: `signal_generator_action` with `reset_safe_state` sets both channels
to sine, 1 kHz, 1 Vpp, 0 V offset and outputs off (source: tool description).

## 7. Error handling

The shared SCPI layer uses these error codes (source: `docs/manual.md` section
15.7):

| Code | Meaning |
|:-----|:--------|
| -100 | Device error |
| -113 | Undefined header |
| -114 | Invalid channel suffix |
| -222 | Value out of range |
| -224 | Invalid parameter |

- `SYST:ERR?` returns the oldest queued error as `code,"message"` and removes
  it. `SYST:ERR:COUN?` returns the queue length. `*CLS` clears the queue.
- An out-of-range value returns `-222` and stops macro playback.
- Do not retry a state-changing command automatically after a communication
  error. Report the error and ask the user before repeating it.
- Command chaining with `;`, `MEAS`, `READ`, `CALC`, sweep, burst and
  arbitrary-waveform commands are not supported; they return `-113`.

## 8. Safety and operating notes

- The generator output can produce real voltages. Verify the load and the
  connection before enabling an output.
- Do not claim that a setting is safe when the load, the signal parameters or
  the connection state are unknown.
- Keep outputs off during setup unless the user explicitly asks to enable them.
- `*RST` and `reset_safe_state` switch both outputs off.

## 9. Known limitations

- Firmware version and firmware-specific differences are not specified in the
  repository.
- The numeric limits above apply to the listed models; other JDS6600 variants
  are not documented.
- FY6900-only waveform names are rejected with `-222`.
- Arbitrary waveforms are not available in this stage.
- Pulse parameters other than `SOUR<n>:PULS:DCYC` are not supported.
- `SYST:LOC` and `SYST:REM` are accepted without effect.
- `STAT` may be omitted in the output command; both forms are documented.
